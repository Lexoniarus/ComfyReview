# Proofs of Concept — laufende Experimente

**Dokumentklasse:** `IN_PROGRESS` · **Rolle:** POC-Index; experimentelle Teilbereiche, keine fertige Produktphase.

POCs sind hier **bewusst ein legitimer Teil der fortlaufenden Produktentwicklung**. Sie testen einzelne Hypothesen technisch oder spielmechanisch, ohne damit eine spätere Architektur oder einen festen Implementierungsplan vorzugeben.

## Aktuell dokumentiert

- [Card Battler — Code- und POC-Stand](card-battler.md): technische Grundlagen vorhanden und laufende Arbeit, aber noch kein abgenommenes Ende-zu-Ende-Spiel.

**ComfyReview bleibt dabei die aktive Anwendung.** Ein POC kann in das bestehende Produkt integriert werden, als Bibliotheksprototyp liegen bleiben, grundlegend umgebaut oder verworfen werden. Eine „approved target“-Formulierung in einem älteren Dokument ist keine automatische zukünftige Verpflichtung.

## POC-Dokumentation

Für neue POCs genügt zunächst: **Fragestellung**, **bereits vorhandener Code/Test**, **aktuell ausprobiert**, **was noch unbewiesen ist**, **welche Entscheidung offen bleibt** und – wenn bekannt – **Ergebnis/Verwerfung**. Keine detaillierte Roadmap, bevor es dafür eine reale Entscheidung gibt.
